# App URLs and tunnel sharing

## The URL to change

Edit `mobile/.env.development.local` and set:

```env
EXPO_PUBLIC_API_BASE_URL=https://your-current-backend-tunnel.example/api/v1
```

Create that ignored local file by copying `mobile/.env.example`. When the FastAPI tunnel address changes, replace this value and restart the Expo development server so the app picks up the new public configuration.

## What happens to the mobile frontend URL?

This is a native iOS/Android app, not a Vite website with a permanent frontend URL. For development sharing, run Expo with `npx expo start --tunnel`; Expo generates and displays a temporary URL/QR code for the JavaScript development server. Share that URL/QR with a tester who has the compatible Expo Go app or the project's development build.

The Expo tunnel and FastAPI tunnel are separate:

- **Expo tunnel:** serves the app bundle during development; generated by Expo for that server session.
- **Backend tunnel:** exposes FastAPI; its base URL is the value in `EXPO_PUBLIC_API_BASE_URL`.

Both services must be running and reachable while a friend tests. Changing one does not change the other. Do not save the changing Expo tunnel URL as if it were the API URL.

## Local device notes

- `localhost` on a phone refers to the phone, not the computer running FastAPI.
- A simulator/emulator and physical device can require different local API hostnames.
- For remote friends, use a current HTTPS backend tunnel address; never expose a development database port.
- Expo tunnel sharing is for development/testing, not production hosting or app-store distribution.
- `EXPO_PUBLIC_*` values are included in the client app. Store only public URLs/configuration there, never secrets.

Production and staging API URLs should later be managed as separate EAS build environments, not copied from a temporary development tunnel.
